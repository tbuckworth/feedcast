But by limiting superposition to only the residual stream and not the MLP[5], the network gets away from this regime, where the noise gets really bad.
Think of it like this. There is a weight matrix connecting two adjacent activation sites[6], one of them is the MLP hidden layer, and one of them is the residual stream just before or after that MLP. Also assume the idealized superposition picture, where there is some set of canonical features for each activation site that are encoded using linear embeddings. But we can't just embed the features, we also need to embed the weights between them.
If feature
If both activation sites use an overcomplete (and therefore non-orthogonal) basis, then you'll also end up with interference in the weights between features (weight superposition). But as long as one of the adjacent activation sites has orthogonal embeddings, the embedded weights between them will also be orthogonally embedded (no weight superposition).
Avoiding weight superposition avoids a large source of noise.
2. There is much more need for compression in the residual stream
If the network can have superposition in either the MLP hidden layers or the residual stream, having it in the residual stream is clearly much more useful.
- All information has to pass through the residual stream, whereas the MLP neurons can be much more limited in what information they have to interact with.
- MLP hidden layers are typically wider than the residual stream, which further reduces their need for superposition.
3. Compensating using some error correction is probably not worth it
Can we have more superposition if the network has error correction? The answer is "yes, but..."
I do think many networks have some error correction.[8] If there is any superposition, there will be noise and therefore some need for error correction, and I do believe there is some superposition. But having superposition in both the residual stream and MLP would cause much more noise, and then I don't think the trade-off is worth it.
Error correction only works on discrete features. Error correction operates by removing the noise from a feature. But in order to do this you need to be able to distinguish noise from signal. If the feature is discrete (only a finite set of allowed values) you can use e.g. step functions built from ReLUs to move the feature to its nearest allowed value. But if it's a continuous feature, then you can't know what part is noise and what part is signal.
Ok, so maybe add some redundancy to help with error correction? But adding redundancy is the opposite of compression. So if you're okay with less compression, why not just remove the source of the noise by removing superposition?
Error correction takes up compute capacity. If we were to add superposition to the MLP, this would create a lot of additional noise, and we would need a lot of additional error correction to deal with this. This error correction needs to be implemented by other MLP neurons, neurons that are now unavailable for other tasks.
In the infinite width limit (as long as you stick to discrete features) you can implement more virtual neurons than neurons, even after taking into account the neurons you need to dedicate to error correction. In realistic networks however, I don't think the gains are worth the cost.
4. The number of alive MLP subcomponents found by VPD is less than the number of MLP neurons
VPD (adVersarial Parameter Decomposition) is a method that decomposes every matrix in a neural network into rank-one subcomponents. Alive subcomponents are components that are used on at least one forward pass. The number of alive subcomponents can be both larger and smaller than the rank of the matrix.[9]
I haven't seen any decomposition of a language model transformer that finds more alive subcomponents in any MLP matrix than that MLP has neurons.[10]

As evidence, she notes that no decomposition she has seen using adversarial parameter decomposition finds more active subcomponents in a language model's MLP matrix than that MLP has neurons.
